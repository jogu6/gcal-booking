# gcal-booking

くまたんグループ向けの **招待&登録(FF14 ver.) 予約フォーム** です。

公開画面は GitHub Pages、予約処理は Google Apps Script、データは Google Sheets を使用します。

## 公開ページ

https://jogu6.github.io/gcal-booking/

## 構成

- `index.html` — GitHub Pages で公開する予約画面
- `Code.gs` — Google Apps Script の Web API
- `assets/evercold.png` — 予約画面の背景・ヘッダー画像
- `README.md` — 本ドキュメント

## データ構成

予約者に見せたくない情報を分離するため、Google Sheets は2ファイル構成です。

### 1. 公開メンバーシート

ファイル名:

`Webグループウェア招待状況一覧`

シート名:

`招待状況`

このシートはメンバーが閲覧・編集する前提です。

| 列 | 内容 |
| --- | --- |
| A | 確認済み |
| B | キャラクター名 |
| C | DC名/ワールド名 |
| D | ステータス |
| E | 備考 |

予約日時・集合DC・Xアカウントなどの予約情報は保存しません。

予約フォームでは、このシートを以下の確認にのみ使用します。

- キャラクター名がメンバー一覧に存在するか
- ホームDC
- 招待ステータス
- 予約対象かどうか

予約可能な基本ステータスは `未招待` です。

### 2. 非公開予約管理シート

ファイル名:

`くまたんグループ 予約管理（非公開）`

シート名:

`予約管理`

このファイルは公開せず、予約管理者だけが参照します。

| 列 | 内容 |
| --- | --- |
| A | キャラクター名 |
| B | 予約日 |
| C | 予約時刻 |
| D | 集合DC |
| E | X利用 |
| F | Xアカウント名 |
| G | 更新日時 |

`X利用` は、X連絡を希望する場合だけ `TRUE` を保存し、未使用の場合は空欄です。

同じキャラクターが予約日時を変更した場合は新しい行を追加せず、既存行を更新します。

予約を取り消した場合は、そのキャラクターの予約行を削除します。

## 予約仕様

- 予約期間: 2026年10月11日〜10月18日
- 10月11日の予約開始時刻: 18:00
- 10月12日以降の対応時間: 08:00〜24:00
- 30分単位
- 最終枠: 23:30〜24:00
- 新しく予約できる最短時刻: 現在時刻から1時間後以降
- 過去の既存予約は自動削除・自動完了しない
- 過去の予約でも取消可能
- 過去の予約から未来枠への変更可能

### 予約枠の表示

公開ページでは予約済み枠を、

`HH:MM 予約済み`

として表示します。

予約者名・集合DC・Xアカウントなどは公開画面には表示しません。

## メンバー確認

予約時はキャラクターフルネームを入力し、`OK` ボタンまたは Enter でメンバー確認します。

比較時のみ以下の正規化を行います。

- Unicode NFKC
- 前後の空白を削除
- 連続する空白を半角スペース1つへ統一
- 英字を小文字化

名前の表示値自体は変更しません。

名前が確認済みになるまでは、DC選択やX連絡設定を表示しません。

予約確定ボタンではブラウザー側のメンバー再検索は行いませんが、Apps Script 側ではデータ整合性を再確認します。

## 集合DC

10月11日・12日の予約だけ集合希望DCを指定します。

選択肢:

- Elemental
- Gaia
- Mana
- Meteor

メンバー確認後、ホームDCを初期選択します。

10月13日以降は集合DCを指定しません。

## Xでの連絡

メンバー確認後に、

`X でやりとりしたい場合はチェックしてください`

を選択できます。

チェックONの場合だけ `X アカウント名` 入力欄を表示します。

入力例:

`@og_ff14`

`@` を省略して入力しても、保存時には自動で付与します。

許可形式:

- 半角英数字
- アンダースコア `_`
- 1〜15文字
- 先頭の `@` は任意

チェックOFFの場合はXアカウントの入力・検証を行いません。

## 予約変更

予約済みの本人が別の日時を予約すると、既存予約を新しい日時へ移動します。

同じ人の予約行が複数作成されることはありません。

予約成功後は予約した時刻までスクロールし、完了メッセージをフローティング表示します。

X連絡を利用する場合は、完了メッセージにも当日のX DM確認案内を表示します。

## 予約取消

画面下部の `予約の取り消し` から行います。

1. キャラクターフルネームを入力
2. `予約を検索します` を押す
3. 現在の予約日時を確認
4. `mm/dd(曜) hh:mm の予約を取り消す` を押す
5. ボタンが2秒間 `予約を取り消してよろしいですか?` に変化
6. 2秒以内にもう一度押すと取消確定

取消成功後は予約行を非公開予約管理シートから削除し、フローティングで完了を通知します。

## 同時予約対策

予約確定処理では Apps Script の `LockService` を使用します。

同じ予約枠に複数人が同時に予約しようとした場合は、先に確定した予約を優先し、後から来た予約は失敗扱いにします。

失敗した利用者には別の時刻を選ぶよう案内します。

## メンテナンス管理

非公開の `くまたんグループ 予約管理（非公開）` に `メンテナンス` シートがあります。

| 列 | 内容 |
| --- | --- |
| A | 有効 |
| B | 開始日時 |
| C | 終了日時 |
| D | 表示メッセージ |

運用手順:

1. 開始日時・終了日時を入力
2. 必要なら表示メッセージを入力
3. `有効` をチェック

有効な期間は予約フォームへ自動反映され、その時間帯は `Xのみ` と表示されます。

メンテナンス時間帯でも予約できますが、`X利用` を有効にした予約だけ受け付けます。サーバー側でもX利用なしの予約は拒否します。

メンテナンス時間帯では集合希望DCの入力欄は表示せず、DC指定なしで予約します。

メンテナンス時間帯と重なる既存予約は、`X利用` が空欄の予約だけ自動キャンセルされます。X利用が `TRUE` の予約は残します。

自動キャンセル判定は予約フォームが予約状況を取得したタイミングで行います。

## Discord Webhook通知

メンテナンスによって **自動キャンセルされた予約だけ** Discordへ通知できます。

Webhook URLはソースコードに保存せず、Apps Script のスクリプトプロパティへ設定します。

プロパティ名:

`DISCORD_WEBHOOK_URL`

Apps Script の「プロジェクトの設定」→「スクリプト プロパティ」から追加してください。

複数件が同時に自動キャンセルされた場合はWebhook送信自体は1回にまとめますが、Discord上では予約1件ごとに独立した埋め込みブロックとして表示します。

通知内容:

- キャラクター名
- 予約日時
- 集合DC
- X利用なし
- 該当メンテナンス時間
- メンテナンスの表示メッセージ（設定されている場合）

通常の手動取消ではDiscord通知しません。

## Apps Script API

現在の API バージョン:

`2026.10.08.6`

主なアクション:

- `action=version` — APIバージョン確認
- `action=slots` — 予約済み枠一覧
- `action=member` — メンバー確認・既存予約確認
- `action=book` — 新規予約・予約変更
- `action=cancel` — 予約取消

すべてのAPIレスポンスに `version` を含めます。

`index.html` 側にも `EXPECTED_API_VERSION` を持たせており、Apps Script のバージョンが一致しない場合は予約画面をエラーにします。

これにより、GitHub Pages だけ更新されて Apps Script の再デプロイを忘れた状態を検出できます。

## Apps Script のデプロイ

`Code.gs` を変更した場合は Apps Script の Web アプリを更新してください。

1. Apps Script プロジェクトで `Code.gs` を最新版へ更新
2. 「デプロイ」→「デプロイを管理」
3. 対象Webアプリの編集
4. 「新しいバージョン」を選択
5. デプロイ
6. 既存の `/exec` URL をそのまま利用

`index.html` だけの変更であれば Apps Script の再デプロイは不要です。

## GitHub Pages

GitHub Pages は `main` ブランチのルートを公開します。

Repository Settings → Pages → Build and deployment

- Branch: `main`
- Folder: `/(root)`

Pages の更新後は、GitHub Actions の `pages build and deployment` が `success` になったことを確認してから公開反映完了と判断します。

## 初期読み込み

予約画面の初期表示では、非公開予約管理シートから予約日・予約時刻を1回の範囲読み込みで取得します。

キャッシュは使用していません。

予約状況の取得に失敗した場合は、予約枠を空きとして表示せず、カレンダーを操作可能状態にしません。
