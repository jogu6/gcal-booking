# gcal-booking

FF14の招待・登録サポート用予約フォームです。

公開画面は GitHub Pages、予約処理は Google Apps Script、データ保存は Google Sheets を使用します。

## 公開ページ

https://jogu6.github.io/gcal-booking/

## 構成

- `index.html` — GitHub Pages で公開する予約画面
- `Code.gs` — Google Apps Script の Web API
- `BoardWebhook.gs` — 掲示板通知のキュー・非同期配信処理（サーバー側）
- `BOARD_WEBHOOK_API.md` — 掲示板WebhookのAPI契約
- `webhook.test.mjs` — 掲示板通知のローカルテスト
- `assets/evercold.png` — 予約画面の背景・ヘッダー画像
- `assets/kumatan.png` — HTML内に表示するギルドロゴ
- `assets/booking-app-icon.png` — favicon・ホーム画面用アイコン
- `README.md` — 本ドキュメント

## データ構成

メンバー情報と予約管理は別のGoogle Sheetsに保存します。祝日表示には、さらに専用の祝日マスター（`Code.gs` の `HOLIDAY_SPREADSHEET_ID` / `祝日一覧`）を参照します。

### 公開メンバーシート

ファイル名:

`Webグループウェア招待状況一覧`

シート名:

`招待状況`

| 列 | 内容 |
| --- | --- |
| A | 確認済み |
| B | キャラクター名 |
| C | DC名/ワールド名 |
| D | 加入日 |
| E | ステータス |
| F | 1時間予約（チェックボックス） |
| G | 備考 |

予約フォームでは、キャラクター名・ホームDC・招待ステータス・予約対象判定の確認に使用します。

予約可能なステータスは、文字列 `ご予約待ち/ご予約中` との完全一致です。`ご予約待ち` と `ご予約中` を別々の値として判定する実装ではありません。

F列が真偽値の `true` の場合は60分、それ以外は30分の予約対象です。A列の確認済みチェックは予約可否の判定に使用しません。

加入日が入力されている場合、日本時間の当日が「加入日＋30日」以降であることも予約条件です。30日未満は、名前確認と予約確定の両方で理由・予約可能になる日を表示して拒否します。未来の予約日を指定しても、予約操作をする当日に30日経過していなければ予約できません。

**加入日が未入力なら、30日経過済みとして扱います。** 日付が入力されているのに解釈できない場合は、管理者への確認を促して受付を止めます。加入日は日付セル、または年を含む `2026/10/1`・`2026-10-01` 形式です。既存予約をこの条件だけで自動取消せず、取消操作も引き続き可能です。

実シートは2行目が見出し、3行目からメンバーデータです。ローカルコードの `CONFIG.MEMBER_FIRST_DATA_ROW` は `3` に修正済みです。公開GASは新版番号の実応答を確認済みです（末尾の「メンバー読み取り開始行の修正」参照）。

予約日時、集合DC、Xアカウントなどの予約情報は保存しません。

### 非公開予約管理シート

シート名:

`予約管理`

| 列 | 内容 |
| --- | --- |
| A | キャラクター名 |
| B | 予約日 |
| C | 予約時刻 |
| D | 集合DC |
| E | 集合ワールド |
| F | 対応方法 |
| G | 連絡先 |
| H | 更新日時 |
| I | 対応状況 |
| J | 対象者に連絡 |
| K | 受付方式 |
| L | 備考 |

新規予約・予約変更の `対応方法` は `ゲーム内` / `コンパニオンアプリ` です。Xサポートの新たな受付は終了しました。過去のX予約の読み取り・通知・取消用に、既存の `X` とG列 `連絡先` は互換性を保ちます。列の削除や既存予約の一括変更・取消は行いません。

同じキャラクターが予約日時を変更した場合は、既存行を更新します。保存処理はA〜H列・K列・L列を更新し、既存行のI・J列は保持します。

60分予約はL列に `1時間予約` を保存し、読み取り時にもこの記載から占有する2枠を判定します。画面は日本語のみです。過去に英語UIから保存された `英語表示から予約` の備考は、既存予約の履歴として保持します。

新規予約・予約変更の書き込み後は、予約管理シートを **予約日 → 予約時刻** の昇順で自動並び替えします。

予約を取り消した場合は、その予約行を削除します。

## 予約仕様

- 初期受付: 2026年10月11日〜10月18日
- 2026年10月12日以降: 当日を含む7日間を基本受付期間とし、「予約設定」の受付終了日で上限を制限
- 10月11日の受付開始: 18:00
- 受付時間: 「受付時間」タブで曜日・祝日別に設定（日本時間）。初期値は全区分09:00〜23:00
- 開始時刻の間隔は曜日・祝日ごとに15・30・60分から設定。予約の長さは通常30分、メンバー表F列の対象者は60分
- 30分予約の最終開始: その日の終了時刻の30分前（23:00終了なら22:30）
- 60分予約の最終開始: その日の終了時刻の60分前（23:00終了なら22:00）。後半30分も空き・対応方法・メンテナンス・受付方式の条件を満たす必要あり
- 新規予約・予約変更は現在時刻の1時間30分後以降（30分枠へ切り上げ）
- 過去予約は自動削除しない
- 過去予約でも手動取消可能
- 過去予約から未来枠への変更可能

画面上の「予約受付期間」は、その日の受付時間を使って最短の開始候補と、受付期間内の最終日の最終開始候補を表示します。最後の日が休止なら、直前の受付日まで戻ります。カレンダーには日ごとの開始・終了時刻を表示します。候補がない場合は、その旨を表示します。

### 予約設定

非公開予約管理スプレッドシートの `予約設定` タブで管理します。

| セル | 内容 |
| --- | --- |
| A1 / B1 | 項目 / 値 |
| A2 | 受付終了日 |
| B2 | 終了日（日付値、または `2026/12/31`・`2026-12-31` 形式など） |

コードは2行目以降のA〜B列を読み、A列が `受付終了日` の最初の行のB列を使用します。通常はA2・B2に設定します。終了日は当日を含み、ローリング7日の末日より後の日付を指定しても受付期間を7日より延長しません。

タブがない、設定行がない、空欄、または日付として解釈できない値の場合は、設定による上限制限を適用しません。終了日が当日より前なら予約可能日がなくなります。2026年10月28日の読み取り確認ではB2は `2026/12/31` でした（固定のコード設定値ではありません）。

### 曜日・祝日別の受付時間

非公開予約管理スプレッドシートの `受付時間` タブを編集します。

| 列 | 内容 |
| --- | --- |
| A | 区分（月〜日・祝日） |
| B・C | 開始1・終了1 |
| D・E | 開始2・終了2 |
| F・G | 開始3・終了3 |
| H | 開始間隔（分）：15・30・60 |

- 1区分につき最大3つの時間帯を登録できます。不要な組は開始・終了を両方空欄にし、3組すべて空欄なら受付休止です。
- 既存の開始・終了は時間帯1として保持します。2026年10月28日の拡張時は、ユーザー設定の全区分14:00〜22:00を保持し、時間帯2・3は空欄、開始間隔は全区分30分にしました。
- 例：月曜のB〜G列を「09:00 / 12:00 / 14:00 / 17:00 / 19:00 / 22:00」、H列を「15」にすると、3つの時間帯の中で15分おきに開始時刻を選べます。昼休み等をまたぐ予約はできません。
- 開始間隔は各時間帯の開始時刻から数えます。開始が09:10・30分刻みなら09:10、09:40、10:10…です。**開始間隔を15分にしても、予約の長さは通常30分・対象者60分のままです。**
- 30分／60分予約は1つの時間帯の中に全体が収まる場合だけ受け付けます。時間帯が隣接していても、2つをまたぐ予約は受け付けません。
- 祝日は専用マスター「祝日一覧」の日付を使用し、曜日の時間帯・開始間隔より「祝日」の設定を優先します。
- 開始は00:00〜23:59、終了は開始より後の時刻（24:00まで）です。日をまたぐ設定はできません。入力順が前後していても、表示は時刻順に整列します。
- 片側だけの空欄、時刻の逆転、時間帯の重複、区分の重複・不足、15・30・60以外の開始間隔はエラーとし、予約画面を操作させません。
- タブ自体がない場合のみ、旧設定との互換用に全曜日09:00〜23:00・開始間隔30分を使います。従来の3列形式も時間帯1として読み取り、開始間隔の空欄は30分です。
- 設定変更は画面の再読み込み、または通常の10分間隔の予約状況取得で反映します。予約確定時にもGASで最新設定を検証します。
- 受付終了日、現在時刻＋90分、メンテナンス、特別受付、予約済み枠の制限も併用します。随時受付でも受付時間外には予約できません。
- 15分刻みの開始でも、既存の30分／60分予約との実際の時間の重なりをサーバーで判定します。予約・変更・取消後は、重なる開始候補をまとめて再取得します。
- 時間を短縮しても既存予約を自動取消しません。確定済み予約は予約管理シートで確認してください。

## 予約枠表示

予約済み枠は、

`HH:MM 予約済み`

として表示します。

予約者名、集合DC、Xアカウントなどは公開画面には表示しません。

## メンバー確認

予約時はキャラクターフルネームを入力し、`OK` ボタンまたは Enter で確認します。

比較時のみ以下を正規化します。

- Unicode NFKC
- 前後の空白を削除
- 連続空白を半角スペース1つへ統一
- 英字を小文字化

名前の表示値自体は変更しません。

名前確認が完了するまでは、サポート方法やDC選択を表示しません。

## 集合DC

2026年10月11日・12日のゲーム内対応では集合希望DCを指定します。随時受付でも同じ日付条件を使用します。

選択肢:

- Elemental
- Gaia
- Mana
- Meteor

2026年10月13日以降、およびコンパニオンアプリ対応では集合希望DCを指定しません。メンテナンス中のゲーム内対応可否は、別途「FF14停止」で制御します。

10月12日の18:30枠までは、集合希望DCに加えて集合希望ワールドも必須です。メンバーシートの `DC名/ワールド名` を読み取り、ホームDC・ホームワールドを初期値として表示します。利用者は必要に応じて変更できます。19:00枠以降は集合ワールドの指定を求めません。予約管理シートでは集合ワールドを集合DCの隣のE列へ保存します。最終列Lは備考です。

## 招待・登録サポート方法

予約時は、その時間帯で利用可能な方法から以下のいずれかを選択します。

- ゲーム内
- コンパニオンアプリ

ゲーム内対応では、10月11日・12日は集合DCを指定します。10月12日の18:30枠までは集合ワールドも必須です。

Xの案内・選択肢・アイコン・アカウント入力を画面から削除しました。GASも `supportMethod=x` や旧 `useX=1` による新たな予約・変更を拒否します。過去のX予約は取消欄で確認・取消できます。

コンパニオンアプリ対応では、リーダーを含む3者専用チャットルームを作成し、その中で招待URLの送付と登録サポートを行います。

予約枠には、その時間帯で利用可能な対応方法をアイコンで表示します。通常予約済み枠では対応方法を公開しません。

## 予約変更

同じキャラクターが別日時を予約すると、既存予約を新しい日時へ移動します。

同じ人の予約行が複数作成されることはありません。

## 予約取消

画面下部の `予約の取り消し` から行います。

1. キャラクターフルネームを入力
2. `予約を検索します` を押す
3. 現在の予約日時を確認
4. 取消ボタンを押す
5. 2秒以内にもう一度押して確定

## 同時予約対策

予約確定処理では Apps Script の `LockService` を使用します。

同じ枠へ複数人が同時予約した場合は、先に確定した予約を優先します。

## メンテナンス管理

非公開予約管理スプレッドシートの `メンテナンス` シートで管理します。

| 列 | 内容 |
| --- | --- |
| A | 有効 |
| B | 開始日時 |
| C | 終了日時 |
| D | 表示メッセージ |
| E | FF14停止 |
| F | X停止（過去のX予約との互換用） |
| G | コンパニオン停止 |

E〜Gはすべてチェックボックスです。新規受付はE（FF14停止）とG（コンパニオン停止）で利用可能な方法を制御します。Fは過去のX予約との互換用に残します。

- FF14だけ停止: Eのみチェック
- コンパニオンだけ停止: Gのみチェック
- 全面受付停止（現在の新規受付）: EとGをチェック
- 既存予約のメンテナンスによる自動取消は従来の対応方法別判定を維持します。X受付終了だけを理由に過去の予約を自動取消しません。

複数のメンテナンス行が重なる場合も、各行のチェック内容を合成して利用可能な対応方法を決定します。既存予約が利用不能になった場合は自動キャンセルし、Discordへ通知します。

## Discord通知

Webhook URLは Apps Script のスクリプトプロパティへ保存します。

プロパティ名:

`DISCORD_WEBHOOK_URL`

Webhook URLが設定されている場合、以下の予約状態変更をDiscordへ通知します。現行コードでは年による通知制限はありません。

- 新規予約
- 予約変更
- 手動取消
- メンテナンスによる自動キャンセル

予約変更では変更前日時と変更後日時を表示します。

メンテナンスによる自動キャンセル通知は、予約1件ごとに独立した埋め込みブロックとして表示します。

初回設定時や疎通確認時は、Apps Script エディタから `testDiscordWebhook` を実行します。

APIバージョン:

`2026.10.28.3`（最大3時間帯／開始間隔／加入30日条件。GAS再デプロイ待ち）

現在の公開WebアプリURL（`index.html` の `API_URL`）:

https://script.google.com/macros/s/AKfycbwOYbRPlEyE6EGLN-lXyCbtsBE9pVPt9sDC1x1r99X2L-oGTB8i282SOKRRyMFJT3Hjcw/exec

旧デプロイID `AKfycbyAVA7JYgDSsa70VODISSq2a0sv2FdqD0UJDEs15WDNs17RuW_eug2_mYta14He4gpVng` は使用しません。

主なアクション:

- `action=version` — APIバージョン確認
- `action=slots` — 予約済み枠・随時受付件数・メンテナンス・特別受付・祝日・受付期間・日ごとの受付時間（`dailyHours`）の取得
- `action=member` — メンバー確認・既存予約確認
- `action=book` — 新規予約・予約変更
- `action=cancel` — 予約取消

すべてのAPIレスポンスに `version` を含めます。

`index.html` 側の `EXPECTED_API_VERSION` と一致しない場合は、予約画面をエラーにします。

ブラウザーからはJSONPで呼び出します。`action=version` は版番号だけを返しますが、`action=slots` は取得時に期限切れメンテナンス行の削除と、利用不能になった予約の自動取消・通知も行います。読み取りだけの検証では `slots` を呼ばず、`version` とシートの直接読み取りを使用してください。

前回公開済みのGASは `2026.10.28.2` です。今回の変更はメンバー表D列に加入日を追加し、旧D〜F列をE〜G列へ移動します。GASは新しい列構成で読むため、画面を先に新版へ配信してから列を挿入し、既存Webアプリを新版へ再デプロイします。

## Apps Script の配置

Apps Script はスタンドアロンプロジェクトとして運用します。

Google Sheets とは `SpreadsheetApp.openById()` で接続するため、スプレッドシート編集者に Apps Script の編集権限を与える必要はありません。

## Apps Script のデプロイ

`Code.gs` または `BoardWebhook.gs` を変更した場合は、ユーザーが既存Webアプリを再デプロイします。GitHubの更新だけではGASへ反映されません。

1. Apps Script プロジェクトで `Code.gs` を最新版へ更新
2. 「デプロイ」→「デプロイを管理」
3. 対象Webアプリの編集
4. 「新しいバージョン」を選択
5. デプロイし、既存Webアプリの公開URLで `action=version` の実応答を確認

`CONFIG.APP_VERSION`、`EXPECTED_API_VERSION`、公開APIの実応答を一致させます。版番号の一致だけでは、すべてのコードやプロパティ・トリガーの反映確認にはなりません。

`index.html` だけの変更なら Apps Script の再デプロイは不要です。

## GitHub Pages

GitHub Pages は `main` ブランチのルートを公開します。

- Branch: `main`
- Folder: `/(root)`

反映を報告する前に、対象コミットのGitHub Actionsが `completed` / `success` であることと、公開HTML・必要な画像がそのコミットの内容と一致することを確認します。pushやActions開始だけでは反映完了としません。

すべてのコード変更前に最新mainと対象ファイルを確認し、既存の予約UI・ロゴ・専用faviconを保持します。本番反映は明示的な指示を受けてから行います。

## パスキーの案内

パスキーは、端末へ保存したログイン用の鍵を、普段の画面ロック解除と同じ指紋・顔認証・端末の暗証番号（PIN）等で使う方法です。予約ページには、登録後の使い方と、設定に不安があれば予約当日に一緒に確認する旨を掲載しています。認証アプリを使う場合の案内・ストアリンクも残しています。この予約ページ自体へパスキー認証を実装する変更ではありません。

説明の参考：[FIDO Allianceのパスキー解説](https://fidoalliance.org/passkeys-2/?lang=ja)。

## 表示言語と登録手引き

画面は日本語のみです。英語翻訳、JA/EN切り替え、保存済み言語設定の参照、英語向け日付表示・ストアリンクへの切り替えを廃止しました。予約送信時の言語指定も行いません。既存GASは言語指定なしを日本語として処理するため、この画面変更にGAS再デプロイは不要です。

登録手引き https://jogu6.github.io/gcal/t/r/ は予約ページ内のカードから案内します。

## 読み込み失敗時

予約状況の初期読み込みがタイムアウトした場合は、最大3回まで自動再試行します。

取得に失敗した場合は、空き枠として誤表示せず、カレンダーを操作可能状態にしません。

## プライバシー

公開メンバーシートには予約日時、集合DC、Xアカウントを保存しません。

予約に関する情報は非公開予約管理シートにのみ保存します。


## 特別受付（随時受付）

非公開予約管理スプレッドシートの `特別受付` シートで、特定期間だけ随時受付を設定できます。

| 列 | 内容 |
| --- | --- |
| A | 有効 |
| B | 随時受付開始日時 |
| C | 随時受付締切日時 |
| D | 通常予約開始日時 |
| E | 表示メッセージ |

随時受付同士では同じ希望時刻に複数人を受け付けられます。60分対象者には後半30分の条件確認も適用します。通常予約と重なる枠は受け付けません。選択時刻は対応開始時刻の保証ではなく、来訪・対応希望時刻の目安です。

随時受付締切から通常予約開始までの時間はアディショナルタイムとして新規予約を受け付けません。通常予約開始後は通常予約者を優先します。当日の状況によっては、設定した締切より前に随時受付を終了する運用も想定しています。

特別受付を後から設定しても、すでに確定している通常予約は通常予約として保持し、同時刻へ随時受付を重ねません。メンテナンスによる利用可能な対応方法の制限、および全面受付停止は特別受付より優先します。

予約管理シートの K 列 `受付方式` には、新規予約時点の条件を `通常予約` または `随時受付` として保存します。

## 対応方法と随時受付

随時受付中も、その時間帯で利用可能な対応方法だけを予約画面にアイコン表示します。FF14メンテナンス中はゲーム内アイコン、コンパニオンアプリメンテナンス中はコンパニオンアイコンを表示しません。両方が重なる場合は受付停止となり、予約できません。

### 最短予約可能時刻

通常予約・随時受付ともに、最短予約可能時刻は「現在時刻＋1時間30分」を30分枠へ切り上げた時刻です。たとえば現在時刻が7:18の場合、1時間30分後は8:48のため、最短予約可能時刻は9:00です。


### Discord の予約変更通知

既存予約と日時・集合DC・集合ワールド・対応方法・連絡先・受付方式のいずれかが実際に変わった場合だけ「予約変更」通知を送信します。同一内容の再送信では「予約変更」通知を送信しません。


### 集合DC列の保存値

予約管理シートの「集合DC」列は、DC指定を省略する予約では空欄にせず `(DC指定省略)` と保存します。アプリ内部ではこの値を「DC指定なし」として扱います。


### Discord通知の集合DC表示

Discord通知でも集合DCを省略した予約は `(DC指定省略)` と表示します。


## 掲示板への予約通知

既存のDiscord通知に加え、gcalの掲示板へ新規予約・変更・取消・メンテナンスによる自動取消を通知できます。公開画面やブラウザーへ受信URLを渡しません。

### 利用者が行う設定

`index.html` の `EXPECTED_API_VERSION` と `Code.gs` の `CONFIG.APP_VERSION` は、どちらも `2026.10.28.3` です。版番号を変更する際は、この2か所と公開APIの実応答の一致を確認します。Webhookの送信確認だけでは、画面側の版番号判定を確認したことにはなりません。

1. Apps Scriptプロジェクトへ更新した `Code.gs` と、新しいスクリプトファイル `BoardWebhook.gs` を反映します。公開用の index.html へ貼り付けないでください。
2. gcalの開発者で対象掲示板の設定 → Webhookの設定から受信URLを発行します。投稿者の名前・自画像は自由に設定できます。
3. Apps Scriptの「プロジェクトの設定」→「スクリプト プロパティ」に `GCAL_BOARD_WEBHOOK_URL` と受信URLを保存します。この作業・Apps Scriptの配備は利用者の担当です。URLをGitHubへコミットしないでください。
4. Apps Scriptエディターから `installBoardWebhookDelivery` を1回実行し、必要なGoogleの権限を許可します。非公開予約管理スプレッドシートに「掲示板通知キュー」を作成し、送信処理を1分間隔で呼ぶトリガーを用意します。再実行しても同じトリガーは増やしません。
5. `testBoardWebhook` を実行し、対象掲示板に「掲示板への接続テスト」が届くことを確認します。その後、Webアプリとして新しい版を配備してください。

### 送信と失敗時

- 予約処理では送信待ち記録だけを追加します。新しい掲示板通信のために予約のロックや応答を待たせません。送信は原則として次回の1分間隔処理で行います。Google側の状況により時刻は前後します。
- 通知IDは変更イベントごとに1つ発行し、通信失敗・429・メンテナンス503では同じIDで再送します。正常な同一予約の保存だけで変更通知を増やしません。
- 「掲示板通知キュー」の状態は「待機」「送信中」「送信済み」「要確認」。入力不正・URL削除・受信停止等は要確認にして無限再送を避けます。予約の保存・取消結果は通知失敗で元に戻しません。
- URLの再発行後はScript PropertiesのURLを更新します。要確認の記録を直して再送する場合、通知ID・本文は変えず、状態を「待機」、次回送信日時を空欄、処理期限を空欄にしてください。本文を直す場合は新しい通知IDにします。
- Discordの既存 `DISCORD_WEBHOOK_URL` はそのまま使えます。掲示板URLが未設定なら、新しい送信待ち記録・トリガー処理は動きません。
- 「掲示板通知キュー」には予約情報を含むため、非公開スプレッドシートに置いてください。今回、既存の予約一覧を公開へ変更していません。

APIの契約・対応形式・文字数・画像・応答と再送方法は [BOARD_WEBHOOK_API.md](BOARD_WEBHOOK_API.md)。これはコードと同梱する仕様書で、利用者のSecret設定やApps Script配備の完了を意味しません。
