# gcal-booking

FF14の招待・登録サポート用予約フォームです。

公開画面は GitHub Pages、予約処理は Google Apps Script、データ保存は Google Sheets を使用します。

## 公開ページ

https://jogu6.github.io/gcal-booking/

## 構成

- `index.html` — GitHub Pages で公開する予約画面
- `Code.gs` — Google Apps Script の Web API
- `assets/evercold.png` — 予約画面の背景・ヘッダー画像
- `README.md` — 本ドキュメント

## データ構成

Google Sheets は、公開用と非公開用の2ファイル構成です。

### 公開メンバーシート

ファイル名:

`Webグループウェア招待状況一覧`

シート名:

`招待状況`

| 列 | 内容 |
| --- | --- |
| A | 確認済み |
| B | キャラクター名 |
| C | DC名/ワールド名 |
| D | ステータス |
| E | 備考 |

予約フォームでは、キャラクター名・ホームDC・招待ステータス・予約対象判定の確認に使用します。

予約可能な基本ステータスは `未招待` です。

予約日時、集合DC、Xアカウントなどの予約情報は保存しません。

### 非公開予約管理シート

シート名:

`予約管理`

| 列 | 内容 |
| --- | --- |
| A | キャラクター名 |
| B | 予約日 |
| C | 予約時刻 |
| D | 集合DC |
| E | X利用 |
| F | Xアカウント名 |
| G | 更新日時 |
| H | 対応状況 |
| I | 対象者に連絡 |

`X利用` は、X連絡を希望する場合だけ `Xでやりとりを希望` を保存し、未使用の場合は空欄です。

同じキャラクターが予約日時を変更した場合は、既存行を更新します。

新規予約・予約変更の書き込み後は、予約管理シートを **予約日 → 予約時刻** の昇順で自動並び替えします。

予約を取り消した場合は、その予約行を削除します。

## 予約仕様

- 初期受付: 2026年10月11日〜10月18日
- 2026年10月12日以降: 過ぎた日を表示せず、当日を含む7日間を常時予約可能
- 10月11日の受付開始: 18:00
- 通常受付時間: 08:00〜24:00
- 30分単位
- 最終枠: 23:30〜24:00
- 新規予約・予約変更は現在時刻の1時間後以降
- 過去予約は自動削除しない
- 過去予約でも手動取消可能
- 過去予約から未来枠への変更可能

画面上の「予約受付期間」は、現在選択できる最短時刻から、受付中の最終日の23:30までを自動表示します。

## 予約枠表示

予約済み枠は、

`HH:MM 予約済み`

として表示します。

予約者名、集合DC、Xアカウントなどは公開画面には表示しません。

## メンバー確認

予約時はキャラクターフルネームを入力し、`OK` ボタンまたは Enter で確認します。

比較時のみ以下を正規化します。

- Unicode NFKC
- 前後の空白を削除
- 連続空白を半角スペース1つへ統一
- 英字を小文字化

名前の表示値自体は変更しません。

名前確認が完了するまでは、DC選択やX連絡設定を表示しません。

## 集合DC

10月11日・12日の通常予約のみ集合希望DCを指定します。

選択肢:

- Elemental
- Gaia
- Mana
- Meteor

10月13日以降、およびメンテナンス時間帯の予約では集合希望DCを指定しません。

## Xでの連絡

メンバー確認後に、

`X でやりとりしたい場合はチェックしてください`

を選択できます。

チェックONの場合だけ `X アカウント名` 入力欄を表示します。

入力例:

`@og_ff14`

許可形式:

- 半角英数字
- アンダースコア `_`
- 1〜15文字
- 先頭の `@` は任意

## 予約変更

同じキャラクターが別日時を予約すると、既存予約を新しい日時へ移動します。

同じ人の予約行が複数作成されることはありません。

## 予約取消

画面下部の `予約の取り消し` から行います。

1. キャラクターフルネームを入力
2. `予約を検索します` を押す
3. 現在の予約日時を確認
4. 取消ボタンを押す
5. 2秒以内にもう一度押して確定

## 同時予約対策

予約確定処理では Apps Script の `LockService` を使用します。

同じ枠へ複数人が同時予約した場合は、先に確定した予約を優先します。

## メンテナンス管理

非公開予約管理スプレッドシートの `メンテナンス` シートで管理します。

| 列 | 内容 |
| --- | --- |
| A | 有効 |
| B | 開始日時 |
| C | 終了日時 |
| D | 表示メッセージ |
| E | 受付方式 |

運用手順:

1. 開始日時・終了日時を入力
2. 必要なら表示メッセージを入力
3. 受付方式を `Xのみ受付` または `受付停止` から選択
4. `有効` をチェック

`Xのみ受付` の期間は対象枠を `Xのみ` と表示し、Xでのやりとりを希望する予約だけ受け付けます。既存のX利用なし予約は自動キャンセルされます。

`受付停止` の期間は対象枠を `受付停止` と表示して選択不可にし、X利用の有無に関係なく新規予約を受け付けません。既存予約もX利用の有無に関係なく自動キャンセルされます。

自動キャンセル判定は予約フォームが予約状況を取得したタイミングで実行します。

## Discord通知

Webhook URLは Apps Script のスクリプトプロパティへ保存します。

プロパティ名:

`DISCORD_WEBHOOK_URL`

2026年常時は、以下の予約状態変更をDiscordへ通知します。

- 新規予約
- 予約変更
- 手動取消
- メンテナンスによる自動キャンセル

予約変更では変更前日時と変更後日時を表示します。

メンテナンスによる自動キャンセル通知は、予約1件ごとに独立した埋め込みブロックとして表示します。

初回設定時や疎通確認時は、Apps Script エディタから `testDiscordWebhook` を実行します。

## Apps Script API

現在の API バージョン:

`2026.10.12.7`

主なアクション:

- `action=version` — APIバージョン確認
- `action=slots` — 予約済み枠・メンテナンス期間・受付期間の取得
- `action=member` — メンバー確認・既存予約確認
- `action=book` — 新規予約・予約変更
- `action=cancel` — 予約取消

すべてのAPIレスポンスに `version` を含めます。

`index.html` 側の `EXPECTED_API_VERSION` と一致しない場合は、予約画面をエラーにします。

## Apps Script の配置

Apps Script はスタンドアロンプロジェクトとして運用します。

Google Sheets とは `SpreadsheetApp.openById()` で接続するため、スプレッドシート編集者に Apps Script の編集権限を与える必要はありません。

## Apps Script のデプロイ

`Code.gs` を変更した場合は Web アプリを更新します。

1. Apps Script プロジェクトで `Code.gs` を最新版へ更新
2. 「デプロイ」→「デプロイを管理」
3. 対象Webアプリの編集
4. 「新しいバージョン」を選択
5. デプロイ

`index.html` だけの変更なら Apps Script の再デプロイは不要です。

## GitHub Pages

GitHub Pages は `main` ブランチのルートを公開します。

- Branch: `main`
- Folder: `/(root)`

## 読み込み失敗時

予約状況の初期読み込みがタイムアウトした場合は、最大3回まで自動再試行します。

取得に失敗した場合は、空き枠として誤表示せず、カレンダーを操作可能状態にしません。

## プライバシー

公開メンバーシートには予約日時、集合DC、Xアカウントを保存しません。

予約に関する情報は非公開予約管理シートにのみ保存します。


## 特別受付（随時受付）

非公開予約管理スプレッドシートの `特別受付` シートで、特定期間だけ随時受付を設定できます。

| 列 | 内容 |
| --- | --- |
| A | 有効 |
| B | 随時受付開始日時 |
| C | 随時受付締切日時 |
| D | 通常予約開始日時 |
| E | 表示メッセージ |

随時受付中は、30分枠を1人分として占有せず、同じ希望時刻に複数人を受け付けられます。選択時刻は対応開始時刻の保証ではなく、来訪・対応希望時刻の目安です。

随時受付締切から通常予約開始までの時間はアディショナルタイムとして新規予約を受け付けません。通常予約開始後は通常予約者を優先します。当日の状況によっては、設定した締切より前に随時受付を終了する運用も想定しています。

特別受付を後から設定しても、すでに確定している通常予約は通常予約として保持し、同時刻へ随時受付を重ねません。メンテナンス設定の `Xのみ受付` / `受付停止` は特別受付より優先します。

予約管理シートの J 列 `受付方式` には、新規予約時点の条件を `通常予約` または `随時受付` として保存します。

## Xでのやりとり

Xでのやりとりを希望する方は、予約前にXのDM（チャット）機能が利用できることを確認してください。当日DM（チャット）が利用できない場合はキャンセル扱いとします。


### Xのみ受付と随時受付が重なる場合

`Xのみ受付` は連絡手段の条件、`随時受付` は受付方式として別々に判定します。両方が重なる時間帯は **Xのみ・随時受付** とし、Xでのやりとりを必須にしたまま、同一希望時刻への複数予約を受け付けます。

`受付停止` と随時受付が重なる場合は `受付停止` を優先し、新規予約は受け付けません。随時受付から通常予約へ切り替えるアディショナルタイムも予約不可です。


### 随時受付の人数表示

随時受付は同一希望時刻に複数人を受け付けられます。2名以上の予約が入っている随時受付枠は、利用者向け画面に予約人数だけを表示します。

- 予約なし: `15:00 随時受付`
- 1名以上: 2行目に `1名予約済み`、`2名予約済み` のように表示
- Xのみ受付と重なる場合も同様に、2行目へ予約済み人数だけを表示

キャラクター名、DC、X利用状況などは表示しません。通常予約は従来どおり `予約済み` とだけ表示します。


### Discord通知

すべての予約イベントをDiscord通知対象とします。

- 新規予約
- 予約変更
- 手動キャンセル
- メンテナンスによる自動キャンセル


### X利用列の保存値

予約管理シートの「X利用」列は、X利用を希望した予約を `希望します` と保存します。未選択時は空欄です。旧データの `TRUE` および `Xでやりとりを希望` も読み取り互換を維持します。


### 最短予約可能時刻

通常予約・随時受付ともに、最短予約可能時刻は「現在時刻＋1時間」を30分枠へ切り上げた時刻です。たとえば現在時刻が7:18の場合、1時間後は8:18のため、最短予約可能時刻は8:30です。
